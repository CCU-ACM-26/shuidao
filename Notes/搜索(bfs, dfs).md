# BFS / DFS 搜索笔记

BFS 和 DFS 是图与隐式图搜索的两条基本路径。它们的时间复杂度在邻接表表示下**都是 O(V + E)**，真正的分水岭不在“谁更快”，而在**搜索顺序**与**空间代价的分配方式**。

> **一句话选型**：无权图求最短 / 最少步数 → BFS；枚举所有可能、回溯、连通性 → DFS。BFS 的空间通常与“宽度”成正比，DFS 的空间通常与“深度”成正比。


## 一、本质区别：搜索前沿的组织方式

| 维度 | BFS | DFS |
|---|---|---|
| 数据结构 | 队列（FIFO） | 递归调用栈 / 显式栈（LIFO） |
| 扩展方式 | 按距离**逐层**向外“地毯式”推进 | 沿一条路径**深入到底**，再回退换路 |
| 首次到达某点 | 在无权图中即**最短路径** | **不保证**最短 |
| 空间峰值 | O(宽度)，可能很大 | O(深度)，通常较小 |
| 天然适配 | 最短步数、层序、多源扩散 | 回溯、连通分量、拓扑排序、环检测 |

DFS 像“钻牛角尖”：能往深走就往深走，撞墙再退回来；BFS 像“地毯式搜索”：先把一步能到的全部探完，再探两步的。DFS 的深入—退回节奏，恰好就是回溯“尝试 → 撤销 → 换一条路”的节奏，所以排列组合、N 皇后、数独这类“枚举所有合法状态”的问题天然用 DFS 写。


## 二、BFS：队列与“层”是全部关键

### 2.1 标准模板（无权图最短步数 / 层序遍历）

```python
from collections import deque

def bfs(start, target):
    q = deque([start])
    visited = {start}
    step = 0

    while q:
        for _ in range(len(q)):          # 当前层的全部节点
            cur = q.popleft()
            if cur == target:
                return step
            for nxt in neighbors(cur):
                if nxt not in visited:
                    visited.add(nxt)      # 入队时立即标记
                    q.append(nxt)
        step += 1
    return -1
```

两个细节决定正确性与效率：

- **在入队时标记 visited，而不是出队时**。出队时才标记会导致同一个节点被多个父节点重复入队，队列规模可能膨胀到不可控。
- `for _ in range(len(q))` 这一层循环是“层”的边界，`step` 只在整层处理完后递增。如果只关心最短距离、不关心层数，也可以把 `dist` 直接存进队列元素中。

### 2.2 为什么队列保证最短路径

BFS 用 FIFO 维护一个“搜索前沿”。队列的性质保证：**距离较小的节点一定先于距离较大的节点被处理**，不会发生深层节点“越过”浅层节点的情况。因此在所有边代价相同的图中，第一次发现某个节点时，走过的边数已经是最少的。BFS 本质上也是 Dijkstra 在边权全相等时的特例：队列就是“退化”的优先队列。

### 2.3 重要变体

**多源 BFS**：把所有源点同时放入队列第 0 层。适用于“多个起点的最近距离”“腐烂橘子”类问题。不需要对每个源点分别跑一遍 BFS，把所有源点当成一个超级源点即可，复杂度仍为 O(V + E)。

**0-1 BFS**：边权只有 0 和 1 时，用**双端队列**：边权为 0 的邻居 `appendleft`，边权为 1 的邻居 `append`。队列中仍能保持代价非降，复杂度 O(V + E)，比堆优化的 Dijkstra 更轻。

**双向 BFS**：从起点和终点同时向外扩展，当两个搜索前沿相遇时得到最短路径。搜索空间从 O(b^d) 降到大致 O(b^{d/2})，在“单词接龙”这类分支因子大、层数深的问题中效果显著。


## 三、DFS：深度、回溯与剪枝

### 3.1 递归模板（图遍历 / 连通性）

```python
def dfs(u):
    visited[u] = True
    for v in adj[u]:
        if not visited[v]:
            dfs(v)
```

图的 DFS 必须维护 `visited`，否则无向图中父子边会导致无限递归。连通分量的求法就是：对每个未访问顶点跑一次 DFS，跑了多少次就有多少个连通分量。环检测的判据：无向图中 DFS 遇到“不是父节点、却已访问”的邻居，说明有环。

### 3.2 回溯框架：“选择 → 递归 → 撤销选择”

DFS 用于枚举所有方案时，核心不是“遍历”，而是**在搜索树上做选择并撤销**：

```python
def backtrack(path, choices):
    if 终止条件:
        记录结果
        return
    for choice in choices:
        if 不合法:  continue   # 可行性剪枝
        path.append(choice)       # 做选择
        backtrack(path, 新choices)
        path.pop()                # 撤销选择
```

组合问题用 `startIndex` 控制下一层从哪里开始，避免 (1,2) 和 (2,1) 重复；排列问题需要 `used` 数组标记已选元素。回溯的本质是穷举，剪枝只是让它“少穷举一些”，不改变最坏复杂度，但常数上的差别可以决定能否过题。

### 3.3 剪枝的五个层次

| 剪枝类型 | 核心问题 |
|---|---|
| **可行性剪枝** | 当前分支已经不满足约束，立即返回 |
| **最优性剪枝** | 当前代价已经差于已知最优解，不再深入 |
| **重复性剪枝** | 同一状态已经搜过，跳过（常配合记忆化） |
| **搜索顺序优化** | 先搜分支更少、更可能出解的方向 |
| **记忆化** | 把子问题的结果存下来，避免重复计算 |

搜索顺序优化往往被低估：在 N 皇后、数独、木棍拼凑等问题中，“先处理候选最少的位置”带来的实际加速可能比单纯加可行性剪枝更大。


## 四、BFS / DFS 的分工地图

| 问题类型 | 首选 | 理由 |
|---|---|---|
| 无权图最短路径 / 最少步数 | **BFS** | 首次到达即最短 |
| 层序 / 按距离分层处理 | **BFS** | 层边界天然清晰 |
| 多源最近距离 | **多源 BFS** | 所有源点同层出发 |
| 连通分量 / Flood Fill | DFS 或 BFS 均可 | 代码量 DFS 更短 |
| 环检测 / 二分图判定 | DFS 或 BFS | 染色 + visited 即可 |
| 拓扑排序 | BFS（Kahn）或 DFS | BFS 按入度删点；DFS 逆后序 |
| 枚举所有排列 / 组合 / 方案 | **DFS + 回溯** | “深入—撤销”天然匹配 |
| 加权图最短路（非负权） | **Dijkstra** | BFS 只管边数，不管权值和 |

拓扑排序的 BFS 版本（Kahn 算法）维护入度表，反复将入度为 0 的节点入队删除；DFS 版本则在回溯时把节点插入结果头部，得到逆后序，再反转即为拓扑序。


## 五、经典题型速查

**Flood Fill 类（岛屿数量 / 最大岛屿面积 / 被围绕的区域）** ：二维网格上对每个未访问的陆地格子启动 DFS 或 BFS，把连通的 1 全部标记掉，每启动一次计数 +1，或累计面积。最大人工岛在此基础上多做一步：第一遍给每个岛屿标唯一 ID 并记录面积，第二遍枚举每个 0，统计相邻不同岛屿 ID 的面积之和。

**拓扑排序类（课程表 / 课程表 II）** ：建图 + 入度表，Kahn BFS 出队顺序即拓扑序；若最终出队节点数小于总节点数，说明有环。

**回溯枚举类（全排列 / 组合总和 / N 皇后 / 数独）** ：DFS 回溯框架，配合 `used` / `startIndex` / 约束检查剪枝。

**最短步数类（迷宫 / 密码锁 / 单词接龙）** ：BFS 层序扩展，用 `step` 或队列中的 `dist` 记录层数，首次到达目标立即返回。


## 六、几条容易踩的坑

**BFS 的 visited 标记时机**：入队时标记，不要出队时标记。出队标记会让同一个节点在队列中重复出现多次，在最坏情况下队列规模失去控制。

**BFS 不是“万能的加权最短路”** ：BFS 最小化的是**边数**，不是权值和。边权不全相等时，边数最少的那条路权值和可能反而更大，必须换 Dijkstra / 0-1 BFS。

**DFS 递归深度**：路径很深的图上递归 DFS 可能爆栈，需要改为显式栈或迭代加深。迭代加深用“逐步放宽深度限制”的方式，兼顾 BFS 的最短性保证和 DFS 的空间优势。

**回溯的“撤销”必须彻底**：`path.pop()`、`visited` 复位、累计量回滚，任何一项漏掉都会让搜索状态被污染，产生看似随机的错误答案。

**连通分量问题在外层通常还有一个循环**：单次 DFS/BFS 只覆盖一个连通块。对全部顶点套一层 `for`，才能处理非连通图。
